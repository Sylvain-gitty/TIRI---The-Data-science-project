## 0. How to read any number here

**Criterion checkability** (ELI18): take every sentence, term, and named criterion in a use case's spec, split it into individual claims ("spans"), and ask of each one: could a machine test this without a human's judgement? A number like `0.31` means about 1 in 3 of this spec's claims is something a machine could check by matching a number, a unit, or a name on a list — the rest ask a human to form an opinion ("promising", "directly transferable", "addresses X"). If checkability did **not** discriminate at all, every use case would land near the same number and the IQR (interquartile range — the spread of the middle half of the 34 values) would be near zero. It is not (see §1).

**Evidence availability** (ELI18): of the abstracts in a use case's pool, what fraction state a number attached to *that use case's own* named criterion, in the same sentence? If it did not work, this would just measure "is this a clinical-trial abstract" — which is why a bare number+unit does not count on its own; the unit has to sit beside a word from the spec's own vocabulary. `NaN` (blank) means **not computable**, never zero: 3 of 6 TIRI use cases (`carbon_capture`, `soil_microbiome`, `tech_forecasting`) have no `performance_criteria` at all, so there is no vocabulary to check evidence against — an absence, not a measured 0%.

**Span accounting.** 1683 spans extracted across all 34 use cases; 33 landed UNCLASSIFIED (dropped from both numerator and denominator, per the pre-registered rule) and 369 tripped both a predicate rule and a judgement rule at once (flagged, not silently resolved — see §4). 0 of 34 use cases fell below the `n_classified >= 3` floor and are excluded from every bar below (none did).

**Label which critic is speaking.** The bars below (IQR, Spearman rho, rank position, top-10 overlap) are hard counts off a deterministic classifier — no judgement call in the arithmetic. Whether the classifier's own rules are the *right* rules (e.g. rule 4's known false-predicate mode on vague performance targets, §4) is a judgement call, labelled as such where it appears.

Within the TIRI-6 stratum alone the IQR is **0.118** — well under 0.2: most of the pooled spread is coming from the TIRI-vs-benchset schema difference, not from genuine use-case-to-use-case variation. ## 3. Rule-set stability

**Pre-registered bar: PASS for evidence availability, VACUOUS for checkability.** The bar needed
rho >= 0.9 and top-10 overlap >= 8/10 between `_UNIT_RE` (discovery.py) and `UNIT_RE`
(probe_metrics.py) for evidence; rho >= 0.8 and overlap >= 7/10 between the narrow judgement
lexicon (`LEADING_STOP` intersect `_METRIC_LEADING_STOP`) and the broad one for checkability.

**Evidence: 🟢 PASS — rho = 0.997, top-10 overlap = 10/10.** The two unit regexes were written
independently, for different purposes, and they agree on which use cases state their evidence in
the abstracts. rho is 0.997 rather than 1.000, i.e. they really are different instruments that
happen to agree. This says the choice between them does not matter; it says nothing about whether
either is *correct*.

**Checkability: ⚪ VACUOUS — the check cannot be passed or failed, because it compared a rule set
against itself.** `checkability_broad` is identical to `checkability` on **all 34 use cases, to a
maximum absolute difference of 0.0**. rho = 1.000 and overlap 10/10 are therefore arithmetic
identities, not agreement between two instruments, and the earlier reading of this line — that
widening the lexicon "does not reshuffle which use cases look checkable, only how checkable the
borderline ones look" — was wrong: it does not change any value at all.

*ELI18: we meant to test the metric twice with a stricter second rulebook, to see whether the
answer held up. The stricter rulebook turned out to score every single use case identically, so we
ran the same test twice and learned nothing from the second run.*

What that means, and it is the more useful finding: **the judgement-hedge lexicon almost never
decides a span's class**, because the classifier's earlier rules resolve nearly everything first.
Widening it therefore has nothing left to act on. So the metric's output is set by the comparator,
enumerated-example and short-span rules, not by the judgement vocabulary the design treated as
half the definition.

🟡 *Judgement call, weakly supported:* the natural suspect is the "≤8 tokens and no finite verb →
PREDICATE" rule sweeping up the short noun phrases that dominate the benchset schema. The
evidence for that is only suggestive — checkability correlates with span count at rho −0.36 within
the benchset stratum and −0.11 pooled — so treat the mechanism as unestablished. **The vacuity
itself is a hard fact; the explanation is not.**

- `ner` and `solar_leo` both have `performance_criteria` populated (3 and 2 entries respectively) whose `target` values are judgement invitations wearing a predicate's clothing: `ner` targets read ['improvement over baseline on news-like content', 'improvement over baseline on news-like content', 'improvement over baseline on news-like content']; `solar_leo` targets read ['better than the incumbent', 'better than the incumbent']. Neither names a number. `cement_binders` is the only TIRI use case whose targets contain a real numeric comparator (`>50% vs OPC`, `>=40 MPa @ 28d`). So "3 of 6 populated" (the old field-presence count) overstates the real predicate count — confirmed, and it is exactly why this probe counts spans instead.

- `tech_forecasting.decision_criteria.must_have` = `['graph', 'database']` — a relabelled term list (two bare nouns), not a decision criterion. The field-agnostic classifier calls both spans PREDICATE (bare keyword) by construction, which is correct classifier behaviour and a spec-quality defect in its own right at the same time: this field is not doing the job its name promises. Confirmed.

- Benchset-28 PICO list fields (short noun phrases: `population`/`interventions`/`outcomes`) were expected to cluster near 1.0 mechanically. Benchset-28 checkability: median **0.780**, range [0.679, 0.906] — confirmed, clustered high.

## 7. What this changes

**The caption does not ship, and that is the pre-registered outcome.** The intended
caption — *"your criteria are mostly judgement calls, and only a small share of these abstracts
state a number — expect to label, not to automate"* — needs a `checkability` number that separates
one use case from another, and this one does not: the middle half of all 34 sit inside 0.055, and
the ranking puts `tech_forecasting` (no performance criteria, the hardest use case in the repo)
3rd of 6 rather than last. A caption drawn from that would be confidently wrong about which use
cases are automatable, which is worse than no caption. S-UCQ Q5 named this in advance — "the
figures do not discriminate → the metric does not ship" — and it is inherited rather than argued
with.

**Two findings survive, and neither is the metric.**

1. 🟢 **Evidence availability is the half that nearly worked, and its NULLs are the result.** IQR
   0.179 against a 0.2 bar, over 31 of 34 use cases. The 3 it cannot be computed for are
   `tech_forecasting`, `soil_microbiome` and `carbon_capture` — the ones with no
   `performance_criteria` to condition on. **The use cases whose corpora we most want to assess
   are exactly the ones whose specs never say what evidence they want.** That is a spec-quality
   defect the funnel can act on today, and it does not need this metric to state it: it is
   `NUMBERS.md` N23's own count (criteria fields populated, 0 of 7 live use cases) with a
   consequence attached.
2. ⚪ **Half the metric's definition was inert.** The judgement-hedge lexicon changed no value on
   any of the 34 use cases, so "predicate vs judgement invitation" was decided entirely by the
   comparator, enumerated-example and short-span rules. Anyone re-attempting this should know that
   before re-deriving the same definition.

**Also confirmed, and it stands on its own:** `ner`'s and `solar_leo`'s `performance_criteria`
targets are unquantified ("improvement over baseline", "better than the incumbent"), so only
`cement_binders` carries a real numeric comparator — "3 of 6 populated" overstates the true
predicate count by 3x. And `tech_forecasting.decision_criteria.must_have = ['graph', 'database']`
is a term list wearing a decision-criteria field name. Both are spec-quality defects visible
without any of the machinery above.

Pre-registered as **descriptive** throughout: no correlation against AUC is claimed at n=34, and
the two strata are reported as rankings, never pooled into one correlation, per S-UCQ Q5.
