# Does the foreign-brief margin predict labelling gain on a clean surface?

Status: **FAIL**. Generated by `scripts/confirm_foreign_brief_validity.py`. $0 — no LLM, no GPU. Read `reports/wf_foreign_brief_detector.md` first; this confirms (or kills) the one salvageable result in it.

🟢 clears the pre-registered bar · 🟡 real but not established · ⚪ engineering finding

## 0. How to read any number here

**Spearman rho** measures whether two rankings move together, from **−1** (perfectly opposite) through **0** (unrelated) to **+1** (identical). Here it asks: *do the collections with the worst foreign-brief margins tend to be the ones that gain most from labelling papers by hand?* If the margin were meaningless, rho would sit near **0**.

**The sign is the claim, not the size.** A negative rho means a bad margin goes with a big labelling payoff — which is the direction that makes the number useful as a *budget* warning. A positive rho would mean the opposite and would kill it outright.

**The bar was fixed before looking: rho ≤ -0.5 on set B, same sign as set A.**

⚠️ **Read the confidence interval, not the point estimate.** At n=7 a bootstrap interval is wide by construction. "Clears the bar" and "established" are different claims and are kept apart below. `jack_min`/`jack_max` show the range when each collection is dropped in turn — if one collection is carrying the whole result, that range is where it shows.

**Label which critic is speaking.** rho, the CI and the jackknife are hard numbers. Whether n=7 on two surfaces amounts to replication is a judgement call, and §2 marks it.

**Pre-registered bar: FAIL.** It required rho ≤ -0.5 on set B with the same sign as set A. Set B's jasper margin gives **rho -0.464** (n=7, CI -1.000 to +0.765) against set A's **-0.929**.

## 2. What this kills, and the second thing it revealed

**The caption does not ship in any form.** `NUMBERS.md` **N33 should be removed from the screen, not
rewritten.** Two independent reasons, either of which would be sufficient:

1. 🟢 **On the clean surface, nothing clears the bar and the confound eats it.** Set B's best
   predictor is the jasper margin at rho −0.464, with a bootstrap interval running from −1.000 to
   **+0.765** — i.e. the data are consistent with the relationship running the *other* way. And
   `rho_given_prevalence` is **+0.143**: once you hold each collection's positive rate constant, the
   sign flips. Prevalence was already the known confound here (rho −0.72 against LOGO transfer in
   `wf_usecase_diversity.ipynb` §7), and this is it doing exactly what it was expected to do.
2. 🟢 **The set-A result was never embedding-independent, and that is visible without set B at all.**
   The same statistic on the same rows gives **−0.929 (jasper)**, **−0.571 (qwen4b, p=0.180, CI
   crossing zero)** and **−0.286 (lexical)**. A property of a *corpus* should not depend that heavily
   on which model measured it. This is the cross-instrument failure from
   `wf_foreign_brief_detector.md` §3 appearing a second time — in the validity result rather than the
   specificity one — and it means the −0.929 headline was one embedding on one burned surface.

*ELI18: on the surface we had already used for many decisions, one particular AI model's version of
this number lined up beautifully with "how much does hand-labelling help here" — a correlation of
−0.93 out of a possible −1.00. On a fresh, never-used surface the same number gives −0.46, and once
you account for how rare relevant papers are in each collection it points the opposite way. Two other
models never agreed with it even on the original surface. So the beautiful number was a coincidence
of one model plus one dataset, which is exactly what a clean surface exists to catch.*

⚠️ **A jackknife cannot save it, and the earlier report leaned on one.** The set-A result survived
dropping any single collection (−0.886 to −0.943), which is why it read as robust. **Leave-one-out
stability measures whether one point is carrying a correlation; it says nothing about whether the
whole surface is.** Those are different failure modes and only a different surface tests the second.

## 3. What this cost, and why it was worth spending set B on

**$0, and about 40 minutes of CPU.** It also spends the one confirmatory read `benchset_v1_large_set_b`
was reserved for, on the single question that would have decided whether a registered `LIVE+SQL`
caption stayed on a screen. The answer is no, which is a better outcome than shipping it: this is a
caption an analyst would have been asked to act on by rewriting a brief that we now have no evidence
is broken.

**What is still true from `P-FB`**, and does not depend on any of the above: the 34×34 matrices are
now persisted rather than recomputed on every notebook run, and *"a brief a wrong brief could replace
is not a brief"* remains sound as a principle — it is the shuffled-brief control, which passes
decisively (AUC 0.777 → 0.498 on SYNERGY, and −0.282 for an LLM reader in
`wf_spec_quality_reader.md`). The derangement control works. The *foreign-brief* variant of it does not.
